# SWIM D-work 運用手順書

コーチ（管理する人）向けの手順です。困ったときは、まずこの文書の該当する章を見てください。

- アプリ：https://swim-d-work.pages.dev
- 管理画面：Supabase（データベース・ログイン）、Cloudflare（アプリの公開・22時の定期実行）、GitHub（プログラムと自動デプロイ）
- 初めて準備するときの手順は `docs/setup.md`、仕組みの詳細は `docs/design.md`

---

## 1. 選手の追加・停止

### 選手を追加する
1. コーチでログインし、下の「選手管理」を開く
2. 名前とメールアドレスを入れて「招待メールを送る」
3. 選手に「SWIM D-work ログインコード」のメールが届く。メールの「はじめて使う方へ」の手順で、ホーム画面に追加してログインしてもらう

- 選手は5人まで（停止中は数えない）
- コードの有効期限は1時間。切れていたら、選手がログイン画面で「ログイン用のコードを送る」を押せば新しいコードが届く
- メールが届かないときは、迷惑メールフォルダを確認してもらう。それでもなければ「8. メールが届かない」へ

### 選手を停止する・再開する
- 「選手管理」で「停止」を押す。停止した選手はログインできなくなるが、予定や記録は残る
- 「停止を解除」で元に戻る
- 停止中の選手は、全員カレンダーに初期状態では表示されない（「停止中の選手も表示する」で表示できる）

### 選手の名前やメールアドレスを変えたい
画面からは変えられません。Supabase の管理画面で直します。
- 名前：Table Editor → `profiles` → その選手の `display_name` を書き換える
- メールアドレス：Authentication → Users → その選手 → メールアドレスを変更し、`profiles` の `email` も同じ値に書き換える

## 2. 機種変更・端末を増やしたとき

1. 新しい iPhone の Safari でアプリを開き、共有ボタン →「ホーム画面に追加」
2. ホーム画面の「D-work」から開いてログインする（メールアドレスを入れると、コードがメールで届く）
3. 右上の「設定」→「通知を有効にする」→「テスト通知を送る」で確認する

古い端末は、使わなくなれば何もしなくてよい（通知が届かなくなった端末の登録は自動で消える）。

---

## 3. 通知が届かないとき

上から順に確認してください。

1. **ホーム画面の「D-work」から開いているか**：Safari で開いていると通知は使えない
2. **iOS のバージョン**：16.4 以上が必要（「設定」→「一般」→「情報」）
3. **通知の許可**：iPhone の「設定」→「通知」→「D-work」で「通知を許可」がオンか
4. **集中モード・おやすみモード**：オンだと通知が表示されないことがある
5. **アプリの設定**：右上の「設定」→「テスト通知を送る」で届くか
   - 「登録された端末がありません」と出たら、「通知を有効にする」を押し直す
6. それでも届かない場合は、「設定」→「この端末の通知をやめる」→「通知を有効にする」でやり直す

通知の種類ごとの条件：
- 選手への通知は、コーチが「保存して選手に通知」（または「選手に通知する」）を押したときだけ送られる。「保存」だけでは送られない（カレンダーに「未通知」と出る）
- コーチへの自動通知は、ドライランドの枠だけが対象。メニュー未設定の枠は、締切後（前日22時以降の翌日分・当日分）の追加・移動のときだけ。それ以外は毎晩22時のまとめ通知で知らせる

---

## 4. 毎晩22時の通知が来ない

1. 翌日のドライランド枠で、メニュー未設定のものがない日は送られない（正常）
2. Cloudflare → Workers & Pages → `swim-d-work-nightly-cron` → Logs（または Metrics）で、22時（UTC 13:00）の実行があるか、エラーになっていないかを見る
3. エラーなら、Supabase の一時停止（5章）か、鍵の不一致（7章の `CRON_SECRET`）を疑う

---

## 5. Supabase が一時停止したとき

Supabase の無料プランは、1週間アクセスがないとプロジェクトが一時停止します。毎晩22時の定期実行が毎日アクセスするので、通常は止まりません。

止まった場合（アプリでログインできない、データが読めない）：
1. https://supabase.com/dashboard にログインし、プロジェクト `swim-d-work` を開く
2. 「Restore project」（再開）を押す。数分で元に戻る。データは消えない

---

## 6. アプリを更新したとき（新しい版が出ないとき）

アプリは裏で新しい版を読み込みます。古い画面のままのときは：
1. アプリを完全に閉じる（画面下から上にスワイプして、D-work を上に払う）
2. ホーム画面から開き直す。これを2回繰り返す

## 7. 鍵の作り直し

鍵は GitHub の Settings → Secrets and variables → Actions に登録してあります。作り直したら、そこを上書きし、GitHub の Actions → Deploy →「Run workflow」で反映します。

| 鍵 | 作り直すとき | 手順 |
| --- | --- | --- |
| `SUPABASE_ACCESS_TOKEN` | 期限切れ・漏れた疑い | Supabase 右上アイコン → Account preferences → Access Tokens で作り直す（権限は全部） |
| `SUPABASE_DB_PASSWORD` | 漏れた疑い | Supabase → Database → Settings →「Reset database password」 |
| `CLOUDFLARE_API_TOKEN` | 期限切れ・漏れた疑い | Cloudflare → Profile → API Tokens →「Edit Cloudflare Workers」テンプレートで作り直す |
| `CRON_SECRET` | 漏れた疑い | 長いランダムな文字列にする（パスワード生成機能などで40文字以上）。Deploy を実行すれば Supabase と Cloudflare の両方に反映される |
| `VAPID_PRIVATE_KEY` と `VITE_VAPID_PUBLIC_KEY` | 漏れた疑い（ふつうは不要） | 2つは必ず組で作り直す。作り直すと、**全員が「通知を有効にする」を押し直す必要がある** |

鍵の作り方がわからないときは、Claude Code に「VAPID 鍵を作り直して」などと頼めば作ってもらえます。

---

## 8. メールが届かない

1. 迷惑メールフォルダを確認する
2. Supabase → Authentication → Emails → SMTP Settings の設定が残っているか（`docs/setup.md` 2章）
3. Gmail のアプリパスワードを削除・変更していないか。変えた場合は新しいアプリパスワードを SMTP Settings に入れ直す
4. 短時間に何度も送ると、しばらく送れなくなる（1時間ほど待つ）

---

## 9. 変更を加えるとき（開発）

- Claude Code に頼むときは、このリポジトリを開いて依頼する。方針は `CLAUDE.md` に書いてある
- 作業はブランチで行い、確認してから `main` に取り込む。`main` に入ると自動で本番に反映される
- GitHub の CI（自動テスト）では、画面操作の通しテスト（`e2e/`）、データベースのアクセス制御のテスト、サーバー処理のテストが動く。失敗していたら取り込まない
